# ТЗ: рендер-независимая карта (два движка: MapLibre + Leaflet)

**Название:** «Картографический слой: общий интерфейс + два рендерера»
**Ветка:** `feat/maplibre` (вся работа здесь, master остаётся Leaflet-снапшотом)
**Характер:** рефакторинг фронта без изменения поведения на MapLibre + новый Leaflet-рендерер + переключатель

## 1. Цель

Снять двойную работу: сейчас любую map-фичу нужно дважды реализовывать в двух несовместимых `app.js`. Цель — один общий код UI/логики (`app.js`) + два тонких рендерера с **одинаковым интерфейсом**. Новая фича пишется один раз и сразу работает в обеих библиотеках. Переключение движка — одной константой или URL-параметром (для демо A/B).

## 2. Текущая завязка на движок (факты из кода)

| Примитив | MapLibre (сейчас) | Leaflet (master) |
|---|---|---|
| Карта | `new maplibregl.Map({..., style: MAP_STYLE})` + NavigationControl + AttributionControl | `L.map(...).setView([55.68,37.70],11)` + tileLayer OSM |
| Точки | `maplibregl.Marker({element})`, пул по ключу | `L.marker(..., {icon: L.divIcon({html, iconAnchor})})` |
| Линии маршрутов | GeoJSON-слой `route-lines`, data-driven paint (`color`,`w`) | `L.polyline(pts)` per engineer в layerGroup |
| Клик по линии | `map.on('click','route-lines')` → `focusEngineer(idx)` | `line.on('click')` |
| Ховер-тултип | Popup `ml-tip`, `setLngLat/setHTML` на mousemove | `line.bindTooltip(...)` |
| Подгонка | `fitBounds([[minLng,minLat],[maxLng,maxLat]])` | `fitBounds(L.latLngBounds(...).pad())` |
| Фокус точки | `flyTo({center:[lng,lat], zoom:15, duration:800})` | `flyTo([lat,lng], 15)` |
| Resize при переключении разделов | `map.resize()` | `map.invalidateSize()` |
| Координаты | везде `[lng,lat]` | везде `[lat,lng]` |

Общее (не трогаем, остаётся в `app.js`): чекбоксы/легенда (`renderMapTools`), таблица маршрута (`renderRouteSteps`), панели, заявки/инженеры/метрики/сценарии, иконки `stopIconHtml/officeIconHtml/unassignedIconHtml/statusIconHtml`, состояние `lineCoords/rid2eng/reqPoints` (канонически `[lng,lat]`), `renderMap/drawAssignmentLayer/focusEngineer/showRequestOnMap` — станут бизнес-логикой поверх интерфейса.

## 3. Целевая архитектура

```
static/
  app.js                  — общий UI/логика/состояние; НЕ содержит maplibregl.* / L.*
  mapEngine.js            — фасад: контракт, переключатель, общий пул точек
  renderers/
    maplibre.js           — реализация фасада для MapLibre (вынесено из app.js)
    leaflet.js            — новая реализация для Leaflet (порт с master)
  style.css               — общие стили (маркеры, тулбары, таблицы)
  renderers/maplibre.css  — стили попапов/тултипа maplibre (вынос)
  renderers/leaflet.css   — стили попапов/тултипа leaflet
  index.html              — грузит выбранный движок (лениво или статично — см. §7)
```

### Контракт `MapEngine` (единый для обоих)

```js
engine = createMapEngine('maplibre' | 'leaflet');        // фабрика
engine.init({ container:'#mainMap', callbacks });        // карта+тайлы+контролы+эвенты
   callbacks = { onReady(), onRouteClick(idx), onRouteHover(idx), onRouteLeave() };
engine.setRoutes(routes);   // routes = [{idx,color,width,tip,coords:[[lng,lat],…]}]
engine.fit(coords, pad);    // coords: [[lng,lat],…]
engine.flyTo(lng, lat, zoom);
engine.resize();            // mapping: maplibre.resize() / leaflet.invalidateSize()
engine.addPoint(key, lng, lat, html, popupHtml);   // ручка → общий пул в app
engine.clearPoints();       // пометить stale
engine.prunePoints();       // удалить stale
```

Правила контракта:
- **Координатная конвенция — единая `[lng, lat]`.** Конверсию в `[lat,lng]` делает только Leaflet-рендерер внутри.
- **Пул DOM-точек — общий** (логика переиспользования/`innerHTML` уже абстрактна, живёт в `app.js`), рендерер отдаёт примитивы: `createPoint(lng,lat,html)` → `{ setPos(lng,lat), remove(), openPopup(html) }`.
- **Линии** — рендерер сам выбирает способ (GL-слой vs `L.polyline`) и сам навешивает на свои линии click/hover → зовёт `callbacks`. Общий код этим не управляет.
- **Тултип** (html строкой из `tip`) — ответственность рендерера (Popup vs `bindTooltip`), единый CSS-класс `.map-tip` для стилизации.

### Переключатель

`MAP_ENGINE = 'maplibre'` (константа). Переопределяется URL: `?engine=leaflet` / `?engine=maplibre`. В `init()` читаем параметр → `createMapEngine`. UI-переключатель НЕ делаем (убирает риск случайно сменить на демо).

## 4. Состав работ и этапы

**Этап 1. Выделить контракт + вынести MapLibre-код (рефакторинг, поведение БЕЗ изменений)**
- `mapEngine.js`: интерфейс, фабрика, общий пул точек.
- `renderers/maplibre.js`: перенос `initMap`/`_addPoint`/`_setRoutes`/`fitCoords`/tooltip/линий из `app.js`; из `app.js` — только вызовы `engine.*`.
- Убрать `state.popup/state.tip/state.markerPool/state.map` в рендерер.
- CSS: вынести `.maplibregl-popup-*`, `.ml-tip` в `renderers/maplibre.css`.
- **Критерий:** полный чек-лист §6 проходит 1:1, диф функциональных правок в app.js минимален.
- *Оценка: 2–4 ч.*

**Этап 2. Leaflet-рендерер (порт с master)**
- `renderers/leaflet.js`: `L.map` + OSM tileLayer; точки через `L.divIcon`; линии `L.polyline` (цвет, weight=width, opacity 0.85, клик, тултип); `flyTo/fit/invalidateSize`; конверсия координат.
- `renderers/leaflet.css`: стили `.leaflet-popup-*`, тултип, переиспользовать общие `.stop-ico` и т.д.
- *Оценка: 2–3 ч.*

**Этап 3. Загрузка и переключатель**
- Решить: статично грузить обе библиотеки+CSS (просто, +150 КБ) ИЛИ лениво по `MAP_ENGINE` (рекомендую: `index.html` без мапл-скриптов, маленький загрузчик инжектит `<script>`/`<link>` нужного движка до `app.js`).
- Класс на `<body>`: `engine-maplibre` / `engine-leaflet` — для scoping стилей.
- *Оценка: 1–2 ч.*

**Этап 4. Приёмка + доки**
- Прогон чек-листа §6 на обоих движках, headless-проверка (как делали для миграции).
- Зафиксировать в README команды запуска обоих движков.
- *Оценка: 1–2 ч.*

Итого ≈ **6–11 часов** (в 1–2 сессии).

## 5. Что НЕ входит в скоуп
- Смена бэкенда/данных/OSRM (не затрагивается).
- Изменение внешнего вида карты, тулбаров, панелей.
- Поддержка третьей библиотеки.
- Дедупликация CDN-зависимостей в целом.

## 6. Чек-лист приёмки (parity MapLibre ⇄ Leaflet)
1. Подложка OSM, навигация, attribution, русские подписи.
2. Нумерованные стопы по цвету инженера, офис 🏢, неназначенные ✕ серые, статусы ◉ по цвету — HTML-маркеры идентичны.
3. Попап по клику на точку — одинаковый контент.
4. Линии маршрутов: цвет инженера, толщина 3 (6 — выбранный), полупрозрачность.
5. Клик по линии выбирает инженера / повторный клик — все маршруты.
6. Ховер-тултип по линии (текст «Инженер N · заявок · км»).
7. Чекбоксы: «все заявки» (forced+disabled при всех маршрутах), «неназначенные», «выполненные» + легенда статусов.
8. Assignment-view: маршрут+стопы выбранного, остальные заявки с номерами, серые/статус.
9. Начальная подгонка по плану; выбор инженера → fit; `focusStop`/«Карта» → flyTo z15.
10. `resize/invalidateSize` при переключении разделов.
11. Смена региона/источника/сценарий — карта перерисовывается корректно.
12. В консоли нет ошибок; перечисленные выше проверки — на `?engine=maplibre` и `?engine=leaflet`.

## 7. Нефункциональные
- Регрессия по текущему MapLibre — не допускается (обязателен прогон чек-листа на maplibre до/после).
- Производительность: не хуже текущей (пул точек сохранён, tooltip не пересоздаётся на каждый mousemove).
- Минимализация связей: `app.js` не знает имён движков (кроме константы) и API конкретных библиотек.
- Коммиты: отдельными логическими единицами (этап = коммит), на `feat/maplibre`.

## 8. Умолчания (по умолчанию беру, можно поменять)
- Движок по умолчанию после перехода: **maplibre**.
- Загрузка библиотек: **ленивая** (по движку) — но если нужен минимум риска, делается статичная (обе CDN сразу).
- Файл документа — `docs/мап-два-движка-ТЗ.md`.
